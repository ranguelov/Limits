# MrBit Limits — QA прототипа и каталог исправлений

Дата проверки: 16 июня 2026. Проверял на проде `https://limits.gurd-6ab.workers.dev` (Brave), кликая каждый экран/действие и читая консоль браузера.

## Что проверено и работает корректно

- **Создание лимита**: карточка → редактор → пресеты, ручной ввод с форматом `1,000`, блок «Resulting changes» (новые иконки 32px, дивайдеры, gap 2px) → Continue.
- **Review «создание / усиление»**: мгновенно, зелёный баннер «takes effect right away», без пароля.
- **Review «ослабление» (повышение/удаление)**: 2 чекбокса + пароль; кнопка Confirm разблокируется только при выполнении всех условий.
- **Подтверждение → тост → дашборд**: статусы Active / Updating / Removing проставляются верно, тосты с правильными заголовками.
- **Иерархия Daily ≤ Weekly ≤ Monthly**: авто-выравнивание соседа срабатывает («Daily auto-aligned / Kept within Weekly»).
- **Удаление**: экран подтверждения → «removal scheduled», карточка переходит в Removing.
- **Сессия**: выбор часов → review → confirm → активная карточка «Up to 4 hours», Time played / Time used.
- **Экран выбора версии** (Popup closed), переключение V1/V2/V3, рендер V1 со state, **Reset all limits**, закрытие тоста по крестику.
- **Ошибок в консоли нет** — ни при загрузке, ни в одном из флоу.

## Найденные баги (исправлены)

### B1 — Даты в прошлом (High, корректность) ✅ исправлено
Базовая дата в `futureDate()` была захардкожена как `new Date(2026,5,10)` (10 июня 2026). Из-за этого все «Active on / Expires on / It will expire on» показывали **11 Jun** — дату в прошлом (сегодня 16 июня).
**Фикс:** дата считается от реального «сегодня» (`new Date()`), т.е. отложенные изменения всегда показывают завтрашнюю дату.

### B2 — Редактирование без изменения значения создавало «пустую» правку (Medium, UX/логика) ✅ исправлено
Если открыть Edit и нажать Continue, не меняя сумму (или выбрать те же часы сессии), система всё равно показывала «Daily limit updated / Applies after 24h» и планировала бессмысленное отложенное изменение.
**Фикс:** при неизменённом значении (та же сумма и тот же период / те же часы) кнопка Continue задизейблена, и в «Resulting changes» ничего не появляется.

## Наблюдения — на твоё решение (НЕ менял)

Это скорее продуктовые решения, чем баги. Скажи, что из этого править.

- **O1.** У карточки в статусе «Removing» по-прежнему доступны кнопки **Edit / Remove**. Может быть осознанно (Edit отменяет удаление), но можно скрыть/заблокировать.
- **O2.** Два активных лимита с одинаковой суммой показывают одинаковые Spend/Remaining (мок — фиксированные 35%). Косметика демо.
- **O3.** Состояние **не сохраняется между перезагрузками** страницы (хранится в памяти). Для демо-прототипа это норм; если нужно «запоминать» — добавлю localStorage.
- **O4.** В коде остался «мёртвый» таймер обратного отсчёта от прежней версии карточек (после компактных карточек он не отображается). Без влияния на работу; уберу при чистке.
